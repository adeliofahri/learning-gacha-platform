============================================================
C. STACK TEKNOLOGI YANG DIGUNAKAN
============================================================

Gunakan satu codebase TypeScript agar lebih mudah dikelola.

Frontend dan backend:
- Next.js App Router
- React
- TypeScript dengan strict mode
- Tailwind CSS
- shadcn/ui untuk komponen UI
- Lucide React untuk ikon
- React Hook Form untuk form
- Zod untuk validasi input
- TanStack Table untuk tabel admin jika diperlukan

Backend:
- Next.js Route Handlers dan server-side modules
- Server Actions hanya untuk operasi yang sesuai; jangan mencampur business logic ke komponen UI
- Service layer untuk aturan bisnis
- Repository/data-access layer untuk query database
- Zod untuk validasi seluruh input API

Database:
- PostgreSQL
- Prisma ORM
- Prisma migrations
- Database transaction untuk operasi koin, gacha, review jawaban, dan inventory

Authentication dan authorization:
- Auth.js atau solusi autentikasi yang kompatibel dengan Next.js App Router
- Login email dan password
- Password hashing menggunakan Argon2id atau bcrypt dengan konfigurasi aman
- Role-based access control: ADMIN dan STUDENT
- Session cookie HttpOnly, Secure pada production, dan SameSite yang sesuai
- Validasi role di server untuk setiap route admin

Testing:
- Vitest untuk unit test dan integration test
- Playwright untuk end-to-end test alur penting

Tooling:
- pnpm sebagai package manager
- ESLint
- Prettier
- Docker Compose untuk PostgreSQL lokal
- Git dan .gitignore

Jangan menambahkan Redis, microservices, WebSocket, atau game engine pada MVP. Aplikasi ini tidak memerlukan real-time multiplayer.

============================================================
F. ATURAN BISNIS: LEARNING SYSTEM
============================================================

1. Admin dapat membuat soal dengan tipe:
   - MULTIPLE_CHOICE
   - SHORT_ANSWER

2. Setiap soal mempunyai:
   - ID
   - subject
   - topic opsional
   - title atau question content
   - type
   - difficulty
   - bounty coin
   - explanation opsional
   - status DRAFT atau PUBLISHED
   - created_by
   - timestamps
   - version

3. Difficulty dan bounty dapat dikonfigurasi. Contoh seed:
   - EASY: 5 coins
   - MEDIUM: 10 coins
   - HARD: 20 coins
   - EXPERT: 35 coins
   Nilai ini hanya konfigurasi demo dan harus dapat diubah admin.

4. Pilihan ganda:
   - Soal dapat memiliki beberapa pilihan.
   - Tepat satu jawaban benar pada MVP.
   - Kunci jawaban tidak boleh dikirim ke browser sebelum jawaban dinilai.
   - Server memeriksa jawaban.
   - Jawaban benar pertama kali memberi bounty.
   - Jawaban salah tidak memberi bounty.
   - Siswa boleh mencoba lagi selama soal belum solved.

5. Isian:
   - Siswa mengirim teks jawaban.
   - Jawaban disimpan sebagai PENDING_REVIEW.
   - Admin dapat memilih APPROVE atau REJECT.
   - Jika APPROVE, bounty diberikan satu kali.
   - Jika REJECT, siswa dapat mengirim percobaan baru jika soal masih aktif.
   - Simpan reviewer, waktu review, dan feedback opsional.
   - Jangan tampilkan jawaban acuan kepada siswa sebelum keputusan admin.

6. Status soal per siswa:
   - UNSOLVED: belum pernah dicoba.
   - ATTEMPTED: pernah dicoba tetapi belum benar.
   - PENDING_REVIEW: menunggu admin.
   - SOLVED: sudah dinyatakan benar dan bounty sudah diberikan.

7. Status SOLVED bersifat global per user-question, bukan per paket.
   Jika soal yang sama terdapat pada beberapa paket, siswa hanya memperoleh bounty satu kali.

8. Paket soal:
   - Paket berisi relasi ke soal.
   - Siswa bebas memilih paket.
   - Siswa tidak wajib menyelesaikan seluruh soal.
   - Progress tersimpan di database.
   - Siswa dapat meninggalkan paket dan melanjutkannya kapan saja.
   - Soal dapat dikerjakan ulang untuk latihan setelah solved, tetapi tidak menghasilkan bounty lagi.
   - Progress paket dihitung dari jumlah soal unik yang berstatus SOLVED di paket tersebut.

9. Perubahan soal:
   - Jangan mengubah histori percobaan yang sudah terjadi.
   - Simpan versi soal atau snapshot konten yang relevan ketika attempt dibuat.
   - Jika soal sudah pernah solved, perubahan bounty tidak boleh memberikan reward tambahan.
   - Soal yang sudah dipublikasikan dan pernah dikerjakan harus dinonaktifkan atau dibuat versi baru, bukan menghapus histori.

10. Anti-duplikasi reward:
   - Gunakan unique constraint pada user_id + question_id untuk solved record.
   - Proses insert solved record dan pemberian bounty dalam satu database transaction.
   - Jika request terkirim dua kali, reward hanya diberikan satu kali.
   - Gunakan idempotency key atau mekanisme setara pada endpoint yang rawan retry.

============================================================
G. ATURAN BISNIS: WALLET DAN TRANSAKSI
============================================================

1. Setiap siswa mempunyai wallet.
2. Currency:
   - COIN untuk gacha.
   - SHARD untuk sistem duplikat.
3. Saldo tidak boleh diubah langsung dari frontend.
4. Setiap perubahan saldo harus memiliki transaction record.
5. Jenis transaksi minimal:
   - QUESTION_REWARD
   - EVENT_BONUS
   - ADMIN_ADJUSTMENT
   - GACHA_SPEND
   - DUPLICATE_CONVERSION
   - SHARD_SPEND jika shard kelak digunakan.
6. amount harus memiliki aturan tanda yang konsisten. Rekomendasi: amount positif untuk penambahan dan negatif untuk pengurangan.
7. Setiap transaksi menyimpan user, currency, amount, type, source/reference, timestamp, dan metadata yang tidak sensitif.
8. Admin adjustment wajib memiliki alasan dan dicatat dalam audit log.
9. Bonus event harus memiliki batas waktu dan aturan klaim agar tidak dapat diklaim berulang.
10. Gunakan database transaction dan atomic update untuk mencegah saldo negatif dan race condition.
11. Jangan pernah menerima nilai saldo baru dari request frontend.

============================================================
H. ATURAN BISNIS: CHARACTER COLLECTION
============================================================

1. Karakter memiliki:
   - ID
   - name
   - description
   - rarity 1 sampai 6
   - image URL/path
   - status ACTIVE atau ARCHIVED
   - created_at

2. Karakter mempunyai kategori:
   - PERMANENT
   - LIMITED

3. Inventory:
   - Setiap user dapat memiliki karakter unik.
   - Simpan quantity atau dupe count.
   - Simpan first_obtained_at dan last_obtained_at.
   - Simpan sumber perolehan melalui gacha history.
   - Avatar hanya boleh dipilih dari karakter yang dimiliki.
   - Karakter yang diarsipkan tetap tampil di koleksi lama.

4. Duplikat:
   - Duplikat dikonversi menjadi Character Shards.
   - Contoh konfigurasi demo:
     1-star = 1 shard
     2-star = 2 shards
     3-star = 5 shards
     4-star = 10 shards
     5-star = 25 shards
     6-star = 50 shards
   - Nilai harus dapat dikonfigurasi.
   - Duplikat tidak menambah skor leaderboard.
   - Simpan riwayat konversi.
   - Jika karakter belum dimiliki, karakter masuk inventory dan tidak dikonversi menjadi shard.

5. Fitur penggunaan shard belum harus memiliki sistem upgrade pada MVP. Buat wallet dan ledger shard agar fitur lanjutan dapat ditambahkan tanpa merombak database.

============================================================
I. ATURAN BISNIS: GACHA
============================================================

1. Gacha hanya menggunakan COIN virtual yang diperoleh dari aktivitas platform atau bonus admin/event. Tidak ada pembelian uang sungguhan.
2. Jenis pull:
   - SINGLE: 1 hasil.
   - TEN_PULL: 10 hasil, harga sama dengan 9 kali harga SINGLE.
   - STEP_UP: lima tahap, hanya untuk banner limited yang mengaktifkannya.
3. Harga contoh:
   - SINGLE: 100 coins.
   - TEN_PULL: 900 coins.
   - Step-up stage 1-5: 100, 150, 200, 250, 300 coins.
   Semua harga merupakan seed/config demo dan dapat diubah admin.
4. Banner:
   - PERMANENT: tidak memiliki tanggal akhir.
   - LIMITED: memiliki starts_at dan ends_at.
   - Banner ENDED tidak dapat digunakan untuk pull baru.
   - Histori banner tidak boleh dihapus.
5. Setiap banner mempunyai daftar karakter, rarity, weight/rate, dan status featured.
6. Rate harus dikonfigurasi dan ditampilkan kepada siswa sebelum pull.
7. Jangan mengarang peluang gacha final. Buat seed demo dengan label DEMO RATE dan dokumentasikan bahwa admin harus meninjau peluang sebelum production.
8. Hasil gacha ditentukan di backend menggunakan secure random generator yang sesuai.
9. Frontend tidak boleh mengirim atau memilih character_id sebagai hasil gacha.
10. Step-up:
    - Maksimal lima tahap.
    - Tahap berjalan berurutan.
    - Siswa harus membayar harga tahap yang sedang berjalan.
    - Tahap kelima menjamin minimal satu karakter 6-star.
    - Jaminan 6-star tidak otomatis menjamin karakter featured.
    - Jika ingin menjamin featured, harus ada konfigurasi guarantee rule terpisah.
    - Simpan progress step-up per user dan banner.
    - Definisikan apakah progress reset setelah menyelesaikan tahap kelima. Default: reset ke tahap pertama setelah siklus selesai.
    - Jika banner berakhir di tengah siklus, jangan menghilangkan histori. Untuk MVP, hentikan pull dan tampilkan status siklus berakhir; jangan menghapus hasil yang sudah didapat.
11. Ten-pull:
    - Satu request menghasilkan tepat 10 hasil.
    - Total harga dikurangi sekali secara atomik.
    - Jika gagal, seluruh transaksi rollback.
12. Setiap pull menyimpan:
    - user_id
    - banner_id
    - pull_type
    - price
    - hasil karakter
    - rarity
    - timestamp
    - step number bila step-up
    - idempotency key
13. Pengurangan koin, penentuan hasil, penambahan inventory/shard, dan penyimpanan history harus berada dalam transaksi database yang konsisten.
14. Tampilkan hasil dan rate secara transparan.
15. Jangan menggunakan dark pattern, timer palsu, atau klaim peluang yang tidak sesuai.

============================================================
J. LEADERBOARD DAN PROFIL PUBLIK
============================================================

1. Lifetime leaderboard:
   - Skor adalah jumlah rarity bintang dari setiap karakter unik yang dimiliki.
   - Rumus: SUM(rarity) untuk karakter unik dengan quantity > 0.
   - Duplikat tidak menambah skor.
   - Skor dihitung dari inventory di server/database, bukan nilai yang dikirim browser.

2. Monthly leaderboard:
   - Skor bulanan adalah total rarity karakter unik yang pertama kali diperoleh pada bulan tersebut.
   - Satu karakter hanya dihitung sekali per siswa dalam satu periode.
   - Simpan tanggal perolehan pertama.
   - Tentukan timezone aplikasi melalui konfigurasi, default Asia/Jakarta.
   - Jangan menghapus data bulan sebelumnya.

3. Tie-break:
   - Jika skor sama, gunakan jumlah soal unik yang solved pada periode terkait.
   - Jika masih sama, gunakan timestamp saat skor tersebut tercapai.
   - Dokumentasikan aturan ini.

4. Profil publik:
   - Username publik.
   - Avatar karakter jika dipilih.
   - Total star.
   - Koleksi karakter hanya jika siswa mengaktifkan public profile atau pengaturan visibilitas yang sesuai.
   - Jangan tampilkan email, password hash, atau data privat.
   - Siswa dapat mengatur is_public.
   - Leaderboard publik sebaiknya hanya menampilkan username, avatar, dan skor.

5. Avatar:
   - Hanya dapat memilih karakter yang dimiliki.
   - Server memverifikasi kepemilikan sebelum menyimpan avatar_character_id.
   - Jika karakter diarsipkan, avatar tetap boleh digunakan kecuali ada alasan moderasi.

13. Proteksi CSRF sesuai mekanisme autentikasi.
14. Validasi file upload: tipe, ukuran, dan nama file.
15. Jangan menyimpan secret dalam Git.
16. Sediakan .env.example tanpa nilai rahasia.
17. Buat audit log untuk tindakan admin penting.
18. Buat prosedur backup database yang dijelaskan di README.
19. Terapkan privacy-by-default pada profil publik siswa.
20. Jangan menampilkan data pribadi siswa pada leaderboard.
